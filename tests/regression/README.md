# Регресійні тести home-hub

Перевіряють ключовий функціонал `cloud/server` і `local` у Docker-мережі **без інтернету**
(продакшен, пошта, Telegram, Expo push недосяжні). Образи збираються з git-ревізії, робоча копія не змінюється.

```bash
tests/regression/run.sh full <ревізія>            # повний набір на чистій базі (~2 хв)
tests/regression/run.sh upgrade <стара> <нова>    # стара наповнює базу → нова на тій самій базі
tests/regression/run.sh compare <стара> <нова>    # full на обох + upgrade + таблиця відмінностей
```

Що покрито (`suite.mjs`):
- **full**: реєстрація/вхід/me, підтвердження email, зміна та відновлення пароля, push-token, telegram-link,
  адмінка (користувачі, запрошення → прийняття, ролі, видалення, налаштування, бекап, telegram), трекери з
  ізоляцією між користувачами, TCP-точки (POST і HQ формати, сміття), socket.io (анонім/зіпсований токен
  відхилено, точка лише власнику), логи й телефон, геозони (вхід → вихід), чат (загальний, особистий,
  непрочитані, пошук), задачі й категорії з коментарями, синхронізація і черга telegram, AI-агент без мережі;
- **full, безпека** (вади з рецензії seccheck 26.11, задачі #6–#8): оператори Mongo (`{"$ne":null}`,
  `?token[$ne]=`) у reset-password, verify-email, forgot-password, login → 400 і пароль жертви не змінено;
  `/api/logs` без imei і з `?imei[$ne]=` — лише точки власника; `GET /api/telegram/queue` — лише admin.
  Такі перевірки спершу проганяються на вразливій версії: мають провалитися, інакше тест нічого не ловить;
- **email** (`email-check.cjs`, усередині контейнера): усі чотири листи збираються встановленим nodemailer;
- **local**: після синхронізації з cloud — вхід хмарним паролем (bcryptjs ↔ bcrypt), трекери, логи, зони, задачі;
- **upgrade**: паролі, захешовані старою версією, старі JWT, усі дані й події геозон — на новій версії.

Відомі вади, що були й до змін, позначаються ⚠ і не валять прогін (`KNOWN` у `suite.mjs`).
Результати — `tests/regression/results/` (не в git).
